# Account System Test Plan

This test plan describes the current behavior of the COBOL account system in `src/cobol`. Execute each case against a fresh program run unless the pre-conditions specify that a prior transaction is required. Record observed behavior in **Actual Result**, then set **Status** to `Pass` or `Fail`.

The current implementation stores one in-memory balance initialized to `1000.00`. It does not validate that credit or debit amounts are positive, so the boundary cases below are included to confirm the current behavior and identify differences to resolve during the Node.js transformation.

| Test Case ID | Test Case Description | Pre-conditions | Test Steps | Expected Result | Actual Result | Status (Pass/Fail) | Comments |
|---|---|---|---|---|---|---|---|
| TC-001 | Display the main menu on startup | Start the application. | 1. Launch the application. | The account management menu is displayed with options 1 View Balance, 2 Credit Account, 3 Debit Account, and 4 Exit. | - | - | Confirm labels and option numbers. |
| TC-002 | View the initial account balance | Start a fresh application run. | 1. Select option `1`. | The application displays `Current balance: 1000.00`. | - | - | Verifies the initial `STORAGE-BALANCE`. |
| TC-003 | Credit the account with a positive amount | Start a fresh application run; current balance is `1000.00`. | 1. Select option `2`. 2. Enter `250.00`. | The application displays `Amount credited. New balance: 1250.00`. The stored balance becomes `1250.00`. | - | - | Standard credit scenario. |
| TC-004 | View balance after a credit | Complete TC-003 or otherwise set the balance to `1250.00`. | 1. Select option `1`. | The application displays `Current balance: 1250.00`. | - | - | Confirms the credit is persisted in memory. |
| TC-005 | Debit an amount less than the balance | Start a fresh application run; current balance is `1000.00`. | 1. Select option `3`. 2. Enter `200.00`. | The application displays `Amount debited. New balance: 800.00`. The stored balance becomes `800.00`. | - | - | Standard debit scenario. |
| TC-006 | View balance after a debit | Complete TC-005 or otherwise set the balance to `800.00`. | 1. Select option `1`. | The application displays `Current balance: 800.00`. | - | - | Confirms the debit is persisted in memory. |
| TC-007 | Debit exactly the available balance | Start a fresh application run; current balance is `1000.00`. | 1. Select option `3`. 2. Enter `1000.00`. | The debit is accepted because the balance is greater than or equal to the amount. The application displays a new balance of `0.00`, and the stored balance becomes `0.00`. | - | - | Verifies the inclusive sufficient-funds comparison. |
| TC-008 | Reject a debit greater than the available balance | Start a fresh application run; current balance is `1000.00`. | 1. Select option `3`. 2. Enter `1000.01`. | The application displays `Insufficient funds for this debit.` The stored balance remains `1000.00`. | - | - | Verifies overdraft prevention. |
| TC-009 | Reject a debit from a zero-balance account | Set the balance to `0.00` using TC-007. | 1. Select option `3`. 2. Enter `0.01`. | The application displays `Insufficient funds for this debit.` The stored balance remains `0.00`. | - | - | Confirms no negative balance is created. |
| TC-010 | Apply multiple credits cumulatively | Start a fresh application run. | 1. Select option `2`; enter `100.00`. 2. Select option `2`; enter `50.00`. 3. Select option `1`. | The first credit produces `1100.00`; the second produces `1150.00`; the final balance display is `1150.00`. | - | - | Confirms each credit reads the latest stored balance. |
| TC-011 | Apply multiple debits cumulatively | Start a fresh application run. | 1. Select option `3`; enter `100.00`. 2. Select option `3`; enter `50.00`. 3. Select option `1`. | The first debit produces `900.00`; the second produces `850.00`; the final balance display is `850.00`. | - | - | Confirms each debit reads the latest stored balance. |
| TC-012 | Attempt a credit of zero | Start a fresh application run; current balance is `1000.00`. | 1. Select option `2`. 2. Enter `0.00`. 3. Select option `1`. | Based on the current COBOL logic, the credit is accepted and the balance remains `1000.00`. | - | - | No positive-amount validation exists in `operations.cob`; confirm whether Node.js should preserve or change this behavior. |
| TC-013 | Attempt a debit of zero | Start a fresh application run; current balance is `1000.00`. | 1. Select option `3`. 2. Enter `0.00`. 3. Select option `1`. | Based on the current COBOL logic, the debit is accepted and the balance remains `1000.00`. | - | - | No positive-amount validation exists; the sufficient-funds condition is true. |
| TC-014 | Enter a debit amount that leaves a fractional balance | Start a fresh application run; current balance is `1000.00`. | 1. Select option `3`. 2. Enter `0.25`. 3. Select option `1`. | The application displays a new balance of `999.75`, and the final balance display is `999.75`. | - | - | Verifies two decimal places are retained. |
| TC-015 | Enter an invalid menu choice below the valid range | Start the application. | 1. Enter menu choice `0`. | The application displays `Invalid choice, please select 1-4.` and continues displaying the menu. No account operation is performed. | - | - | Verifies the `WHEN OTHER` branch. |
| TC-016 | Enter an invalid menu choice above the valid range | Start the application. | 1. Enter menu choice `5`. | The application displays `Invalid choice, please select 1-4.` and continues displaying the menu. No account operation is performed. | - | - | Verifies the upper invalid range. |
| TC-017 | Continue operating after an invalid menu choice | Start a fresh application run. | 1. Enter menu choice `9`. 2. | TC-018 | Exit from the main menu | Start the application. | 1. Select option `4`. | The loop ends and the application displays `Exiting the program. Goodbye!`. | - | - | Verifies normal termination. |
| TC-019 | Ensure no menu is displayed after exit | Start the application. | 1. Select option `4`. 2. Observe the output after the goodbye message. | No additional menu or account operation is displayed after the exit message; the program stops. | - | - | Confirms `CONTINUE-FLAG` is set to `NO`. |
| TC-020 | Preserve a balance across operations in one run | Start a fresh application run. | 1. Select option `2`; enter `300.00`. 2. Select option `3`; enter `100.00`. 3. | TC-021 | Read the stored balance through the data module | Start a fresh application run. | 1. | TC-022 | Write and then read a balance through the data module | Start a fresh application run. | 1. Invoke the data module with operation `WRITE` and balance `1234.56`. 2. | TC-023 | Ignore an unsupported data operation | Start a fresh application run; stored balance is `1000.00`. | 1. Invoke the data module with an operation other than `READ` or `WRITE`, such as `DELETE`. 2. | TC-024 | Ignore an unsupported operations command | Start a fresh application run; current balance is `1000.00`. | 1. Invoke `Operations` with a command other than `TOTAL `, `CREDIT`, or `DEBIT `, such as `TRANSFER`. 2. Select option `1` or read the balance through the data module. | No transaction occurs, no operation-specific message is displayed, and the balance remains `1000.00`. | - | - | Documents current silent no-op behavior for unsupported operation codes. |
| TC-025 | Verify the balance remains unchanged after an insufficient debit | Start a fresh application run; current balance is `1000.00`. | 1. Select option `3`; enter `1500.00`. 2.
